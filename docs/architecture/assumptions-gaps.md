# Assumptions and gaps

This document separates facts visible in the source tree from checks that still
require the ALT Linux VM.

## Known assumptions

1. **OCR language mismatch.** `extractor.rs` defaults to `eng+rus` when
   `DOCUMENT_SEARCHER_OCR_LANG` is unset. The Flatpak manifest currently sets
   `DOCUMENT_SEARCHER_OCR_LANG=eng` and installs `eng.traineddata` only. Do not
   silently change either side until the Linux OCR environment is checked.
2. **Generated Cargo sources.** `src/flatpak/generated-sources.json` is a
   Linux-generated artifact and is not treated as present or verified on
   Windows. It must be produced with `cargo flatpak-generator` after the
   lockfile is stable.
3. **GSettings runtime.** The schema XML and build/install instructions exist,
   but schema discovery and persistence need a Linux/native and Flatpak smoke
   test. `load_settings()` intentionally returns `None` when the default schema
   source cannot find the schema.
4. **Embedded resource runtime.** `build.rs` still compiles the GResource only
   for the Linux desktop feature. The generated bytes are embedded through
   `include_bytes!`; successful CSS lookup and desktop startup still require a
   Linux build and runtime check.
5. **Desktop validation.** Windows `--no-default-features` tests validate core
   Rust behavior only. They do not validate GTK, Libadwaita, ashpd portals,
   GIO launch behavior, OCR native libraries, Flatpak permissions, or schema
   installation.

## Deliberate architecture choices

- The runnable UI is procedural `build_ui()` code. Blueprint and the old
  disabled widget modules are not runtime components.
- Scan indexes and search results are in memory. GSettings stores only
  `scan-path`; no database or persistent index is assumed.
- `gio::File::for_path(...).uri()` and
  `gio::AppInfo::launch_default_for_uri` are used for file opening rather than
  manually concatenating `file://` with `Path::display()`.

## Specification gap

`docs/specs/03-system-design-spec.md` and older planning notes describe an
older Relm4/Blueprint component layout. The current runnable path is the
procedural `app.rs` plus `RuntimeBridge`, `Worker`, and `model/*` contracts.
The requirements specification remains user-owned and is not rewritten as
part of this synchronization.

## Linux VM checklist

- Build `cargo build --release --features desktop` with the GTK/GLib toolchain.
- Confirm CSS is found from the embedded GResource.
- Confirm default and persisted `scan-path` through GSettings.
- Exercise portal folder selection, cancellation, granted filesystem access,
  and GIO file opening.
- Verify image and scanned-PDF OCR with the actual tessdata languages.
- Generate `flatpak/generated-sources.json`, build with `flatpak-builder`, and
  run `org.gtk.DocumentSearcher`.

Until those checks run, all of these remain gaps rather than verified claims.
